# 08 UI 自绘规格（Gio 版）

> 事实源：上游 `08-UI与交互设计.md`（§3 交互规格/§3.5 重复裁决交互/§3.6 GUI 优化差异/§4 识图校正流/§5 防错清单）
> 与 Electron 版 08（页面/动画原始规格）。上游 §1 移植清单、§2 api 适配层**不适用**（无 WebView，直调即适配，00 §4）。
> 本文 = 逐页布局与绘制设计 + 棋盘绘制 ops + 动画帧循环 + 长列表虚拟化 + IME + 防错映射；页面/动画细节以 Electron 版组件为逐项锚点。

## 1. 通用约定（主题/字体/路由/组件基座）

- **主题色板**：沿上游对齐 Electron 版色板；色值锚点=Electron 版 src/renderer 主题定义，M0' 锁定为 Go 常量表（internal/ui/theme.go），全仓禁散落硬编码色值。（M0' POC 期以 internal/ui/poc_palette.go 过渡：色值即 Electron global.css :root 锚点，M1' 落 theme.go 后删除。）
- **字体**：go-text/typesetting 整形 + 系统字体扫描（Noto Sans CJK 回退链）；启动时注册一次全局复用。中文渲染回退与系统字体发现=**POC-3 排险项**，结论回填本节。（**已回填**：gio 默认 shaper 内建 fontscan 系统回退，未注册亦可渲染中文；M1' theme.go 采用"显式注册 Noto CJK 四件（Sans/Serif × Regular/Bold）+ 内建回退兜底"；棋子字用 Noto Serif CJK SC 近似 Electron 楷体意图——Linux 无 KaiTi。）
- **布局原语**：layout.Flex/Stack/List/Grid/Inset，尺寸用 dp；弹窗=Stack 顶层 + 半透明遮罩（拦截底层输入）；toast=Stack 顶层非模态浮层（不注册输入事件）。
- **页面路由**：internal/app 维护页面栈（主页 + 7 入口 + 弹窗层）；每页一个 state struct（铁律 #G3 独占）；页面切换触发旧页 dispose（自动保存/输入锁解锁挂接，07 §2）。
- **组件基座**：gioui.org/widget/material 基件（按钮/输入/滚动条）+ 自绘专用组件（棋盘/棋子/动画/棋子选择器）；不引第三方 widget 集（依赖白名单）。

## 2. 主页（7 入口）

- 布局：标题区 + 居中列式 Flex 的 7 张入口卡（残局选关/人机对战/人机 LLM/LLM vs LLM/双人对弈/残局工作室/棋谱库）+ 全局设置入口。
- 入口卡=自绘圆角矩形（clip.RRect）+ 标签文本 + 点击态（widget.Clickable，hover 高亮）。
- 残局选关卡副标题显示语料 puzzles 分类计数（state 预计算投影 corpusTypes，不触发解析）。

## 3. 棋盘组件（BoardView 的 Gio 实现——最大复用资产）

### 3.1 布局口径（沿上游 08 §3 逐字保留）

- `cell = min(w/9.6, h/10.6)`；交点坐标 = origin + col/row × cell；命中换算=rect 缩放反算，点击取最近交点（阈值 cell/2）。
- 棋盘区外留白按口径自然产生；组件自适应父容器约束。

### 3.2 绘制 ops（自底向上）

1. 底色：`clip.Rect` + `paint.Fill`（木色/主题底）。
2. 线路：横线 10 条、纵线 9 条（边线贯通、中间纵线在楚河汉界区断开）——`clip.Stroke`（线宽 ~1dp）；九宫斜线 ×4；炮位/兵位标记（小折线组，位置与 Electron 版 boardArt SVG 逐元素对照）。
3. **楚河汉界文字**：两段中文（"楚河"、"汉界"，纵排方向沿上游），text 包 + typesetting shaping。
4. **纵线号**：红方底部汉字一~九（右→左）、黑方顶部数字 1~9（左→右），沿上游记谱口径；实现时与 Electron 版 SVG 逐元素核对（M2' 验收项）。
5. 棋子：圆形底（`clip.Oval`，红/黑双面色系）+ 单汉字（车马相仕帅炮兵…，typesetting 居中整形）；字与底色对比沿上游。
6. 选中态：选中棋子外圈高亮环（`clip.Stroke`）；**合法目标高亮**：选中后从 `rules.AllLegalMoves` 白名单取目标点，绘制小圆点/空位角标（落子提示）。
7. 将军提示：被将方帅/将格高亮（沿上游）；终局态覆盖结算横幅（见 §5）。
- 绘制性能：Gio 全帧重绘；若 POC-1 实测布局开销超标，棋盘静态层（底色+线路+标记+河界字）可缓存离屏 image 每帧贴图——**POC-1 结论决定是否采用**，交互层（棋子/高亮）始终实时绘制。

### 3.3 交互

点击选中→合法目标高亮→点目标格→飞行动画→真正落子（`vm.executeMove`）；终局后禁手（#6）；动画窗口忽略输入（#1）；点空白处/再点选中子=取消选中（沿上游）。

## 4. 220ms 两阶段飞行动画（帧循环实现）

- 两阶段语义沿上游：阶段一=选中子自起点向目标插值移动；阶段二=到达落定（被吃子随之消失）。easeOutCubic 缓动。
- **实现（Gio 帧循环）**：
  1. 发起：记录 `anim{from, to, start=time.Now(), active=true}`，`window.Invalidate()` 排帧；
  2. 每帧（FrameEvent）：`t = (now-start)/220ms`；`t ≥ 1` → **权威结束**（帧时间戳判定，对应上游"220ms 定时器权威、transitionend 不可靠"）：`active=false`，调 `vm.executeMove(move)` 完成真正落子（防错 #2），停止排帧；
  3. `t < 1` → `p = easeOutCubic(t)`，棋子绘制位置 = lerp(from, to, p)，`window.Invalidate()` 请求下一帧。
- 动画期间：BoardView 吞掉棋盘点击（#1）；AI 触发不挂在点击而挂在 executeMove 完成回调（#3，见 §11）。
- 撤销/新局/离页发生在动画中：立即作废 anim（active=false，不落子），走对应取消链（#4）。

## 5. 四对局页（双人对弈/人机对战/人机 LLM/LLM vs LLM）

共同骨架（沿上游 §3.1~3.4）：棋盘（§3/§4）居中 + 侧板（对局信息：回合/步数/用时/将军标记 + 走法记录开关 + 走法列表）+ 操作按钮行（新游戏[确认框]/悔棋/保存/分享）。

- **人机页**：执红/执黑可选、引擎类型（内置 AI）与难度选择；AI 应手经 Runner goroutine（00 §4），思考中状态条 + 取消入口（对齐上游）。
- **人机 LLM / LLM vs LLM 页**：
  - LLM 配置卡：endpoint 四字段（baseUrl/apiKey/model/preset）表单（widget.Editor+IME）、三槽位（红/黑/助手）、测试连接、掩码显示（`****`+末4位，防错 #8）、预设选择（DR-005 映射恒发关闭参数，**无思维链开关**）；
  - 流式消息区：chunk 追加文本渲染（每 chunk Invalidate），VetoFeedback 否决链条目；
  - **立即保存粘性置底**（上游 §3.6 优化 3）：侧板 = Flex 竖排{滚动区(layout.List), 固定底部按钮行}——滚动时按钮恒可见；
  - 配置空侧跟随对方（上游-DR-012 业务规则照搬）。
- **重复裁决交互**（上游 §3.5 逐条）：k=2 → 非阻塞 toast（#11，Stack 顶层浮层）；k=3 判负 → `vm.resign(side)` 复用终局结算弹窗（#12，文案含判负方）；对手非玩家的重复和棋 → 自动 `agreeDraw`；对手是玩家 → 确认框（接受和棋/变着继续，拒绝记 declined，k≥4 强制和）。悔棋/新局重置 declined 与未决框（state 收口点内联，07 §3）。
- **新游戏确认框/终局结算弹窗**：Gio modal 层组件（遮罩+面板+按钮组），全页共用。
- **求解进度非阻塞悬浮条**（上游 §3.6 优化 2，工作室用）：Stack 底层棋盘完整可交互 + 顶层浮条不注册 pointer 事件（对应 `pointer-events:none`），求解中重复发起由 state 守卫拦截，无关闭入口（TC-SOL-007 语义）。
- **求解结果关闭置顶**（上游 §3.6 优化 1，工作室用）：结果面板标题行常驻头部（Flex 竖排{固定头部行含 × 按钮, 滚动内容区}），底部关闭按钮保留兜底。

## 6. 残局选关页（含演示播放器）

- 关卡列表：语料 puzzles 分类 → 关卡卡（标题/步数/难度投影，`DifficultyFromMoveCount`）；难度筛选与排序（state 投影）。
- 进入关卡：求解挑战（isWinningFirstMove 判定模型首着）/ 演示播放（puzzleDemo 状态机：步进/自动/回退控制条 + 棋盘动画复用 §3/§4，走子逐手应用）。
- LLM 求解辅助：proposeSolveFirstMove → `IsWinningFirstMove` 裁判 → 结果 toast；助手配置借用注记（DR-009）。

## 7. 残局工作室（三 Tab）

- Tab 结构：顶部 Tab 条（widget.Enum 自绘）+ 内容区。
- **摆盘校验 Tab**：棋盘摆盘模式（点击格位→棋子选择器轮换放置/清除），合法性校验经 rules（inPalace 等未导出函数按 K9 口径评估是否导出，一行改动须登记）；校验结果面板。
- **求解 Tab**：载入局面 → Solver Runner（进度悬浮条 §5）→ 结果面板（§5 置顶关闭）；入库（solve_status）与"进入对战"联动。
- **识图 Tab**：图片载入（粘贴/文件选择——文件对话框走 00 §4 开放决策项）→ VisionReadBoard（无取消入口，按钮 disabled 防重入，K33 口径）→ **人工校正流**（上游 §4）：识图结果 9×10 网格 → 点击纠错（候选棋子选择器）→ 重新提交/直接采用 → 进入演示/对战。
- 助手配置弹窗（AssistantConfigDialog 自绘）；DR-009：助手槽全空时运行时借用对战配置（黑→红），消息区注记来源与识图风险、toast 提示，不写入助手槽。

## 8. 棋谱库（14 万局长列表虚拟化）

- 行点击 → 重放器视图（棋盘 + 步进/自动播放控制 + 走法列表 + 进入对战）；导出 PGN（协议快照面）。

## 10. 中文 IME

- 所有文本输入一律 `widget.Editor`（内建输入法接入与预编辑 preedit 渲染）：LLM 配置卡、搜索框、摆盘备注、求解参数等。
- X11/Wayland/Windows/macOS 输入法协议覆盖与 **WSLg fcitx5 实测=POC-3 排险项**（重点：预编辑串位置与提交时序）；结论回填本节；若 WSLg IME 有缺陷，记录 workaround（如剪贴板粘贴兜底）并登记 KNOWN_ISSUES。
- **已回填（M0' POC-3 + 用户验收定论）**：gio v0.10.3 的 X11 后端无 XIM 客户端（无 XOpenIM），fcitx5(XIM) 无法输入；**用户手测确认 Windows IME 经 RDP 亦无法输入**——WSLg 下中文键盘输入全路径不可用（**KG-003**）。
- **中文内容输入口径（KG-004，已验证）**：WSLg 剪贴板桥接对 CJK 乱码且有损（Windows→WSL 方向），Ctrl+V 仅适用于 ASCII（API Key/URL 可用）；中文经"从 Windows 剪贴板粘贴"路径（`powershell.exe Get-Clipboard` 管道，UTF-8 正确）可靠输入——POC-3 按钮已端到端实证，**M4' LLM 配置卡沿用此按钮（异步化，铁律 #G3）**。混合文本禁止静默反解码（桥接处字节已丢，不可逆；`clipboardMojibakeRecover` 仅作纯中文段抢救工具）。
- 关联 gio/WSLg 事实：`InvalidateCmd{At: 未来时刻}` 不排帧（KG-006，帧循环一律立即排帧）；窗口标题栏中文 □ 为 WSLg 标题解码缺陷（KG-005，应用侧不可修）。ChangeEvent 在提交后可靠回读。
