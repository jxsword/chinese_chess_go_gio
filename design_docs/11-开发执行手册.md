# 11 开发执行手册（Gio 版）

> 沿用上游 11 手册的执行模型/五段模板/验收流/复审/跑偏表/同步纪律；
> **§4 为 M0'~M7' 完整启动提示词**（首次写全，全新会话逐字粘贴即可开工，不留模板引用）；
> §5 里程碑验收流与 §8 文档-代码同步纪律照搬上游（测试过→提交→手测→修复→验证→再提交；不出现代码领先文档）。

## 1. 执行模型

1. AGENTS.md 常驻（每次会话自动读取）；
2. **一里程碑一全新会话**（逐字粘贴 §4 对应启动提示词）；
3. 子任务串行循环（§2 五段模板），一任务一 commit；
4. 里程碑收尾：复审（§6）→ 质量门 → PROGRESS.md 更新 → **用户手动验收**（§5）→ 合入 main（可选打 tag）；
5. 会话纪律：不连做两个里程碑；引用文档编号而非粘贴全文；代理想改架构即停，走 DR 流程。

## 2. 子任务五段模板

```text
【范围】只做 <T' 编号+标题>，涉及 design_docs/<编号 §节>，参照实现 <上游/Electron 文件锚点>
【先写测试】按 09 文档对应节：上游 spec 翻译用例/金标准对拍/快照/表驱动用例先行（红→绿）
【验收】质量门全绿（gofmt/vet/go test ./... -race）+ 本任务专属验收（§3 任务表）
【禁止】超出范围的重构；改动 internal/ 六包复制物；意译协议；跳过/删除用例变绿；引入白名单外依赖
【提交】feat(mN'): 描述（Decision: DR-Gxxx 尾行；PROGRESS.md 同步勾选）
```

## 5. 里程碑验收流（用户手动验收门，**每里程碑必经**）

```text
1. 代理完成该里程碑全部子任务（自动化测试先行、逐任务 commit）→ 质量门全绿
2. 代理更新 docs/PROGRESS.md（完成项勾选、已知问题、手测指引）
3. 【暂停】代理明确列出"请手测清单"，等待用户验收
4. 用户手测：
   - 无 bug → 回复确认 → 代理提交里程碑收尾（tag 可选）→ 进入下一里程碑
   - 有 bug → 用户列出现象 → 代理按 §6.2 修复（禁止删/跳用例变绿）→ 回归全绿 → 再提交 → 回到第 3 步
5. 纪律：验收通过前不开工下一里程碑；修复 commit 不得混入新功能
```

## 6. 复审与修复提示词

### 6.1 里程碑代码复审（验证门前两轮）
- 第一轮·语义一致性：对照 design_docs/{对应文档} 与**上游/Electron 版锚点**逐节检查——状态层翻译逐用例对应（09 §3）、交互规格逐条（08 §3~§5）、事件名与 00 §4 清单一致、Gio 绘制与 08 §3.2 对照。
- 第二轮·缺陷扫描：竞态（后台直写 UI/state、迟到响应、输入锁、动画窗口）、取消链（requestId/context 全覆盖）、事件总线阻塞/背压、goroutine 异常传播、错误消息泄 Key、`-race` 报告。
- 输出 P0~P3 缺陷清单（文件:行号 + 设计依据）；P0/P1 立即修复回归，P2/P3 记 docs/KNOWN_ISSUES.md（编号自 KG-001 起）。

### 6.2 测试失败修复
先判实现错还是锚点/金标准错；改锚点或金标准必须给上游/Electron 版依据并单独 commit；复制物测试失败=复制或环境问题，禁止改复制物代码变绿；禁止删/跳用例变绿；输出失败原因分类统计。

### 6.3 回归护栏（合入 main 前）
对照 AGENTS.md 铁律逐条自检，可 grep 项机器验证：#G1（六包 import 面无 gio/net-http）、#G2（复制物 diff 审计口径）、#G3（后台 goroutine 无 state/UI 直写——-race + 评审）、#G6（关闭参数恒发）、#G7（掩码）、#G8（白名单）；输出自检表，任一不满足即中止。

## 8. 文档-代码同步纪律

1. **先文档后代码**：任何行为/接口/参数变更先改 design_docs/ 对应章节（同一 commit 或文档先行 commit），再动代码；
2. 每个子任务 commit 同步勾选 docs/PROGRESS.md 对应条目；
3. 每里程碑收尾 PROGRESS.md 必含：完成清单、验收门结果、性能实测数据（POC/动画/列表/引擎应答）、已知问题（KNOWN_ISSUES 链接）、下一里程碑手测指引；
4. 禁止代码领先文档多个提交；发现漂移立即停下补文档。
